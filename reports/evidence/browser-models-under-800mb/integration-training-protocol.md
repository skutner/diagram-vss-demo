# Independent diagram reader: integration and training protocol

## What does an independent reader actually have to supply?

### Takeaway
The model does not draw: it produces ordered SOP nodes, with per-request confidence and dependencies, for the existing engine on its own canvas. A flat action classifier or a language model that merely returns plausible JSON is not this contract. This is a design proposal, not an implementation or an experiment.

### Cited Findings
- At investigation start the local repository was on `main`, HEAD `1667ead753b890dac553ef07d9b1246747c36d6e`, exactly the requested source baseline; tracked and staged diffs were empty. The independent canvases share an engine/legend implementation but have separate world, undo/redo and context; all ready readers receive the same message. Late-loading readers may initially copy the Rules drawing, a deliberate existing behavior, not ongoing shared state. [README:12–14,41–49](../../../README.md#L12-L14); [ui.js:8–22](../../../docs/js/ui.js#L8-L22); [ui.js:1635–1641](../../../docs/js/ui.js#L1635-L1641).
- UI passes each reader its own canvas shape/group names, previous `last`, and displayed labels; it formalizes first, gates request groups, applies named-dependency and destructive safety holds, then calls that reader's `engine.run(nodes, {overrides})`. An engine clarification can become a pending choice; an unread part is reported separately. [ui.js:1271–1287](../../../docs/js/ui.js#L1271-L1287); [ui.js:1297–1349](../../../docs/js/ui.js#L1297-L1349); [logic.js:3188–3211](../../../docs/js/logic.js#L3188-L3211).
- SOP nodes have `{id, type, args}`, with `command`, `question`, `fact`, `rule`, and `mention` wire types. A reference is `{ref: id}`; names and arrays can also be argument values. The text parser enforces unique IDs and definition before reference (SSA). Generated JSON passed directly to `engine.run` must enforce these invariants itself: it bypasses `parse`. [logic.js:11–13,37–57](../../../docs/js/logic.js#L11-L57); [logic.js:687–707](../../../docs/js/logic.js#L687-L707).
- A description becomes an earlier `mention` node whose reference is used by an action; the engine resolves it against the canvas, asks on ambiguity and errors if absent. The joint reader preserves written names, creates same-message wire references, reads context/description roles and attaches original character spans and a non-enumerable `unit` to group wires; `NEXT_CONTEXT` advances local context after each proposed request. Existing context resolution is not a guarantee that an ambiguous reference is correct. [neural.js:115–135,146–155](../../../docs/js/neural.js#L115-L155); [neural.js:261–339](../../../docs/js/neural.js#L261-L339); [logic.js:697–707](../../../docs/js/logic.js#L697-L707).
- **Validation trap:** `Legend.validate` emits a warning for an unknown key, not an error; it errors for invalid enum values and nonnumeric numbers. Despite the warning's “ignored” wording, `Engine.run` copies all keys into handler args, so do not assume unknown keys were stripped. Some documented engine keys such as `position2`, `anchor2`, `region` are not legend questions and are intentionally supported by the joint reader; blindly rejecting all non-legend keys would lose existing expressiveness. [logic.js:94–105,169–180](../../../docs/js/logic.js#L94-L105); [neural.js:156–159](../../../docs/js/neural.js#L156-L159); [roles round-trip:107](../../../training/neural/ROLES_ROUNDTRIP.md#L107).
- **Atomicity trap:** default execution is partial: each wire snapshots/rolls back its own failed patches and explicit `{ref}` dependents are skipped; independent earlier wires remain. `partial:false` rolls back the message. Successful changes are committed together as message history, not an all-or-nothing multi-command guarantee. Names without wire references are not equivalent to explicit dependency edges; `holdNamed` makes a conservative same-message heuristic, not universal dependency proof. [logic.js:145–195](../../../docs/js/logic.js#L145-L195); [ui.js:1103–1135](../../../docs/js/ui.js#L1103-L1135); [live dependent failures](../../diagram-e2e-five.md#L91-L102).
- The modern joint route calls no Rules formalizer; legacy classifier/QA, zero-shot and embedding branches **do** take the Rules' cut and references, even if externally marketed as neural. `requireJoint` blocks accidental fallback. [neural.js:138–144,342–368](../../../docs/js/neural.js#L138-L144); [neural.js:204–226](../../../docs/js/neural.js#L204-L226).
- `NeuralKit.setModels` normally mutates global `ACTIVE`; ModernBERT sets `activateCut:false`, has its own gate/cutter and is outside `crossReads` and old votes. Shared Transformers.js custom cache and asynchronous stale pruning are additional isolation hazards: pruning retains an explicit union of known models. [neural.js:146,457–459](../../../docs/js/neural.js#L146); [ui.js:16–22,416–458](../../../docs/js/ui.js#L16-L22); [neural.js:725–785,810](../../../docs/js/neural.js#L725-L785); [plan:74–89](../../../training/neural/MODERNBERT_PLAN.md#L74-L89).

### Inferences
- Proposed isolated adapter: `formalize(text, {names,last,texts})` produces ordered request records `{span:[c0,c1], nodes:[...], confidenceEvidence, status, reasons, dependsOn}` plus `notes` and `unread`. Offsets must be half-open offsets into the exact original JS input string (UTF-16 code units), including Unicode and punctuation; preserve mapping if spelling correction or normalization changes the text. The adapter then creates the existing non-enumerable node `unit`/`span` grouping or an explicitly reviewed equivalent. Example intermediate output: `[{"id":"m1","type":"mention","args":{"shape":"circle","color":"red"}},{"id":"n1","type":"command","args":{"action":"set","target":{"ref":"m1"},"color":"blue"}}]`. It is not a promised model output.
- Build output schema from the actual enabled legend questions, kinds and canonical enum values, **not** its Rules cue lists, plus a separately documented mechanical engine interface for named supported non-legend fields. Reject/hold unexpected keys, enum/type errors, duplicate IDs, forward or missing refs, malformed spans and invalid JSON before execution; do not silently delete meaningful fields. If a necessary field cannot be represented in a legend-only schema, report the contract gap and hold the affected request rather than inventing language-to-legend equivalences. The schema conveys allowed symbols, not hand-written word/synonym mappings. A model must learn semantics from annotated examples or a separately supplied pretrained model, not borrow Rules cuts/references.
- Use the model's own multi-request cut head or a generator that explicitly returns multiple ordered action records, not a single flat message classifier. Preserve names, labels, numbers, mention descriptions and context references; keep references unresolved when the source/context cannot identify them and ask instead of selecting a shape. Preserve the original long message; chunk/window only with an explicit offset map and cross-window dependency handling, and report any unprocessed suffix rather than drop it.
- Give each requested action its own calibrated confidence and group its supporting mentions with it. Hold the entire group for missing calibration, malformed/partial output, truncation or uncertain interpretation, then propagate explicit and named dependencies transitively; still allow truly independent understood actions. Model score or token probability alone is not a calibrated action confidence. Ensure actual engine errors/dependency blocks are recorded after gate decisions. Maintain destructive safety and never force execution of a truncated/invalid group. [Existing gate](../../../docs/js/neural-confidence.js#L246-L280); [ModernBERT fail-closed wrapper](../../../docs/js/neural.js#L569-L579).
- Future integration must own a separate model instance/session, cache namespace or reviewed cache retention union, model/version/loader options, confidence artifact, cutter and canvas; never set `ACTIVE`, alter global runtime settings, add to `crossReads`/votes, or replace old weights, gates, canvases or their observed results. Verify load failure, stale pruning, late load, unload, concurrent reads, serialization/reload and old reader snapshots independently. A no-change live regression is evidence for its tested cases only. [Five-reader legacy snapshots](../../diagram-e2e-five.md#L125-L133).

### Gaps
- The adapter schema, allowable mechanical extensions, exact grouped-transaction expectations and unsupported/ambiguous-reference UX require design review; none was implemented or runtime-verified here. Schema validity alone cannot prove intent, downstream handler success, or safe execution.

## What training and export are credible on Apparatus or a small CPU?

### Takeaway
Apparatus has actually completed one carefully bounded ModernBERT-base run; this does not establish current availability or the fit of an arbitrary model. Head training, small-encoder fine-tuning and cautiously sized causal LoRA/QLoRA are future options, with architecture-specific feasibility and export still to prove.

### Cited Findings
- Sanitized 2026-11-03 inventory: Ubuntu 26.04.1 LTS x86_64, i7-12700H, 14 cores/20 threads, 30.57 GiB RAM, RTX 3060 **Laptop** 6144 MiB, compute 8.6, NVIDIA driver 595.99.02; snapshot reported GPU `Reset` and no runnable Torch environment found in bounded search. Snapshot free memory and health are not current guarantees. Apparatus inventory: `browserLLM/docs/browser_encoder_notes/apparatus_finetuning.md:3,16–31,44–64`.
- Later, on 2026-11-04 after the owner's reboot, the ModernBERT report records recovery `None`, native CUDA probes and a separate Python 3.12.16 / Torch 2.15.0+cu132 / Transformers 4.57.6 / tokenizers 0.22.2 environment. One epoch on 24,698 messages/54,584 requests used FP32 eager, checkpointing, microbatch 1, accumulation 16, 3,412 updates and 4,652.95 s; no request or message was truncated in that training run. The earlier M1 MPS pilot stopped at 17 pairs at the fixed host-memory guard. This supersedes the old fault for that historical run only, not today's GPU state. [modernbert report:3–48](../../modernbert.md#L3-L48); [CUDA resource/lock plan](../../../training/neural/MODERNBERT_PLAN.md#L112-L157).
- State-only estimates for FP32 weights + gradients + Adam moments are roughly 16 bytes per trainable parameter: approximately 1.00 GiB for 67M or 2.23 GiB for 149.7M parameters, excluding activations, heads, allocator, workspaces and CUDA context. Attention memory can scale with sequence length squared; checkpointing trades compute for activations. LoRA saves base gradient/optimizer state but still needs backward activations; 4-bit base training supports extra trainable parameters, not arbitrary full updates to integer weights. Prior feasibility: `browserLLM/docs/browser_encoder_notes/apparatus_finetuning.md:101–116,120–133`; [HF memory anatomy](https://huggingface.co/docs/transformers/model_memory_anatomy); [PEFT LoRA](https://huggingface.co/docs/peft/developer_guides/lora); [bitsandbytes](https://huggingface.co/docs/transformers/quantization/bitsandbytes).
- The actual ModernBERT export's dynamic-activation q8 changed decoded actions/cuts across runtimes. A separately registered repair retained 8-bit weight storage but used FP32 computation and Basic graph optimization; its 19 fixtures passed Python/Node/real-browser WASM parity. This was not retraining, and compressed download is not inference RAM; WebGPU was not validated. [modernbert report:55–96](../../modernbert.md#L55-L96); [export plan:7–25,49–79](../../../training/neural/MODERNBERT_EXPORT_PLAN.md#L7-L25).
- Training and JS must share tokenizer IDs, first-piece indices, masks, padding, Unicode, spans and truncation; the existing ModernBERT contract uses wordwise BPE prefix spaces and 128/512 request/message caps, explicitly holds truncated requests and reports unread suffixes. [training plan:21–37](../../../training/neural/MODERNBERT_PLAN.md#L21-L37). A gold-to-training-to-decoder round trip found prior silent label loss and overlapping spans: data conversion is itself a necessary check. [roles round-trip:8–22,59–62](../../../training/neural/ROLES_ROUNDTRIP.md#L8-L22).
- The separate VSA repository's browser benchmark is masked-token prediction rather than diagram structural quality; requested WebGPU is not proof of individual operator placement. Its M1 measurements cannot be transferred as task latency or accuracy. VSA browser README: `browserLLM/vsa-semantic-space/browser/README.md:1–3,16–22,33–60`.

### Inferences
- Start with a frozen pretrained encoder plus supervised cut/action/value/role/span heads, then, only for measured semantic/value failure, consider one separately registered full fine-tune or ordinary LoRA. Do not retrain to repair tokenizer, conversion, graph optimizer or export parity defects. Small full encoder training may fit on the historical GPU at microbatch 1 and checkpointing; all capacity numbers besides the cited completed run are estimates. A small CPU can execute encoder inference or head training, but latency, RAM, thread behavior and usability must be measured on the actual target; no laptop-CPU result is established here.
- A small causal model can be evaluated as an alternative that emits the same ordered structured output. If later fine-tuning is justified, SFT with LoRA or QLoRA is a plausible 6 GiB **pilot**, not proof of fit: pin exact architecture, tokenizer/chat template, adapter targets and trained modules, optimizer, input+output lengths, batch/accumulation, activation checkpointing and 4-bit stack; count weights, KV/cache, logits, activations and peak allocator plus process overhead. Confirm architecture/kernel/quantization support from the exact trainer/runtime version; do not assume a generic LLM recipe supports a chosen model. Preserve long examples with explicit chunks/holds, never filter them away. The original PEFT/quantization sources above substantiate methods, not this unselected architecture's support.
- Model and deployment provenance should bind base revision, licenses, source datasets and example IDs/hashes, annotations, prompt/chat template and tokenizer revision/normalization, conversion and offset policies, training code/config/seed, checkpoint, graph/shards, adapter merge and precision, all runtimes and calibration artifact. Compare native training model, merged adapter, float export and each selected q8/q4 deployment on exact tokenization, decoded full actions/roles/references/cuts and calibrated decisions; calibration must use the finalized deployed artifact. Quantization is not training feasibility evidence.
- Record total bytes actually required to load the selected model including tokenizer/config, graph and every shard, as well as separately shared runtime assets; the assigned cap is **strictly less than 800,000,000 bytes**, not 800 MiB. Track transfer/cold cache and persistent disk separately from peak CPU/browser/WASM and GPU memory; a sub-cap artifact may still not fit the target device.

### Gaps
- Current Apparatus health, idle status, thermal/power conditions and installed environment were not queried. No inference, training, service, GPU inspection or external download occurred in this investigation. Target CPU/browser devices, model-specific causal architecture, context limits, memory and latency acceptance budgets remain unselected; no candidate's fit or quality is claimed.

## What future experiment would make a defensible comparison?

### Takeaway
Predeclare a disjoint fit/calibration/test experiment, assess whole requested actions and actual dependency outcomes, and freeze model, decoder and confidence before inspecting test outcomes. The historical ModernBERT and ten-action results are frozen product baselines, not evidence of an architecture ranking.

### Cited Findings
- The 2026-11-04 ModernBERT formalization test had 745 test messages / 1,745 requested actions: 16 right, 0 wrong, 1,625 held, 104 unread, 0 executed extras; execution wrong share 0/16, AUROC 0.888655 and right share 0.9169%. All 16 accepted were questions; the registered ≥20% right criterion failed. These are formalizations and confidence/dependency decisions, **not** 1,745 live drawings. The frozen model used one epoch versus shipped SOP-BERT's eight with different settings. [modernbert report:50–53,127–167](../../modernbert.md#L127-L167).
- Its first-cause diagnosis reports 844 downstream-head and 445 cutter cases covering 1,185 wrong/extra proposals and 104 unread requests. Some reference mismatches need separate explanation; a wrong star output also occurs in the original float model, before conversion. The negative result was closed without gate tuning or retraining. [modernbert report:169–203](../../modernbert.md#L169-L203).
- The frozen eleven-turn live fixture contains ten requested actions and one unsupported control. Rules/VSS/SOP-BERT/VSS-BERT/ModernBERT got 9/8/7/3/1 right; e.g. one Rules label was engine-rejected, and four VSS-BERT actions were blocked by a missing prerequisite. The M1/Chrome WASM median formalization times were SOP-BERT 71 ms and ModernBERT 537 ms; they exclude loading and differ in shared work and calls. This dependent, tiny fixture does not establish broad quality ranking, AUROC, or fair model-architecture superiority. [fixture:1–3,31–45,97–125,161–166](../../../training/sketch/diagram_e2e_cases.json#L1-L3); [five-reader report:35–60,91–102,148–173](../../diagram-e2e-five.md#L35-L60).
- Repository policy permits all annotated data to be read and trained on; a future experiment can still predeclare and preserve its own disjoint partitions. The prior ModernBERT protocol selected thresholds with five-fold calibration, fold-local priors/tables and cost-10 objective, with test results excluded from threshold choice. [AGENTS.md:43–47,73–94](../../../AGENTS.md#L43-L47); [training plan:81–103](../../../training/neural/MODERNBERT_PLAN.md#L81-L103); [report:129–139](../../modernbert.md#L129-L139).

### Inferences
- **Proposed hypothesis, to preregister before any run:** a single new, independent supervised structural reader using the schema/cutter/gate contract above can achieve useful correct coverage while holding uncertainty, without changing existing readers. Concrete success on a fresh frozen, disjoint test: all of (1) cost-10 score > 0, (2) ≥20% of requested actions semantically right, (3) ≤5% of executed actions wrong including extras, and (4) exact declared deployment parity and legacy isolation checks pass. These reuse the earlier quality bar for a new protocol, not a claim of improvement on a different test. Require an adequate predeclared number of executed actions and uncertainty intervals before interpreting the wrong fraction; an ask-everything reader cannot meet coverage.
- Freeze candidate checkpoint/revision, data IDs and grouped split, model/head architecture, loss, optimizer, training budget, seed, test gold and semantic matching before training or evaluation. Split by whole message and group linked turns/near duplicates together, ensure no training/calibration/test leakage, and preserve all realistic long examples. Reserve unseen-trigger and unsupported cases, multiple actions in one message, ambiguous mentions, same-message and cross-turn references, long suffixes, names, relative positions, colors, shapes, label/rename, arrows, layout and questions. Never tune on the ten-action fixture; do not regenerate its old baseline. Use fresh frozen tests distinct from all fitting and prompt examples.
- Calibrate per-action confidence on calibration only (e.g. message-grouped out-of-fold predictions, including an ask-all candidate; select cost-10 threshold and tie rule before looking at test). Freeze calibration features, graph and threshold before test. Score semantic correctness of the **whole** action including roles/values/references, not just action label; a correct wire proposal is not necessarily a successful engine mutation or correct answer. Report right, executed wrong, held/asked, unread, engine rejected, and dependency-blocked separately; extras are unrequested executions. Report cost score `100*(right-10*(wrong+extras))/requested`, wrong execution share `(wrong+extras)/(right+wrong+extras)` (undefined when zero executions), right/request coverage, confidence AUROC and risk–coverage curve, and seen/unseen trigger strata. Do not use per-message exactness as headline. Audit pairing, overlapping cuts, unsupported controls, and dependency propagation.
- Two different comparisons: (a) a controlled experiment on the same disjoint training examples, labels, split, supervision, optimization/tuning opportunity and explicit compute/update budget, reporting any unavoidable architecture differences; (b) a frozen shipped-product comparison including its actual weights, historical training and gates. Do not call (b) equal-data or equal-budget. Preserve the 1,745-action and eleven-turn results as historical references, not fresh tests or regenerated baselines. After any future evaluation, classify first causes with counts/examples by data/annotation, tokenizer, cutter, model heads/semantics, references, calibration, export/runtime, or engine; stop/report a failed registered criterion rather than tuning on test. Prior evaluation principles: `browserLLM/docs/browser_encoder_notes/repository_evidence.md:220–240`; [plan reporting](../../../training/neural/MODERNBERT_PLAN.md#L91-L110).
- Predeclare device budgets and record provider/runtime/version, cache state and model file bytes. Separately measure native small-CPU, browser WASM CPU and WebGPU (where actually available): cold download/load, tokenizer/model initialization, time to first token **where applicable**, time to first valid command, complete message latency and warm p50/p95, throughput, thread count, browser responsiveness and output readback. Track memory before/during load and inference, JS heap, process RSS and WASM/GPU metrics where observable without double-counting shared/unified memory; disclose unavailable metrics. Browser and native CPU runs do not imply GPU placement or parity.

### Gaps
- This is a proposed future hypothesis and acceptance procedure, not an authorized run, proof of feasibility, model selection, code review, or runtime verification. Exact fresh dataset size, minimum execution count, confidence interval rule, model identity and minimum device/latency/memory budgets must be frozen before that separate experiment.
