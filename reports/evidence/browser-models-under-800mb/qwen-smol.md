# Qwen, SmolLM and Llama: small instruction models

## Which current families and models are relevant?

### Takeaway

Qwen3.8 exists, but the smallest Qwen3.8 release found is 27B; Qwen3.5-0.8B is a newer small candidate than Qwen3-0.6B. SmolLM3 is 3B, so the older SmolLM2-360M-Instruct remains useful under this limit. These are candidate artifacts, not measured task performance.

### Cited Findings

- The official Qwen search returns Qwen3.8-27B, Flash-Next and 2.4T-A95B; searches for Qwen3.9 and Qwen4 returned none on 2026-11-04. This is a publisher-search result, not proof that no other unpublished model exists. [Qwen3.8 search](https://huggingface.co/api/models?author=Qwen&search=Qwen3.8&limit=100); [Qwen4 search](https://huggingface.co/api/models?author=Qwen&search=Qwen4&limit=100); [27B metadata](https://huggingface.co/api/models/Qwen/Qwen3.8-27B/revision/1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0?blobs=true).
- [Qwen3.5-0.8B](https://huggingface.co/Qwen/Qwen3.5-0.8B/blob/2fc06364715b967f1860aea9cf38778875588b17/README.md) is post-trained, not its separately published `-Base`; its original is vision-language, but the listed GGUF and text ONNX choices here are for text. It defaults to non-thinking, permits `enable_thinking=True`, and warns that the 0.8B model can get stuck in thinking loops. Its card claims multilingual support and tool calling, not guaranteed correctness. Qwen3.5 does not officially support Qwen3's `/think` and `/no_think` soft switches.
- [Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/README.md) is instruction-following and distinct from `-Base`; it defaults to thinking, with `enable_thinking=False` as the documented hard switch. Its card claims support for 100+ languages and tool use.
- [SmolLM3-3B](https://huggingface.co/HuggingFaceTB/SmolLM3-3B/blob/a07cc9a04f16550a088caea529712d1d335b0ac1/README.md) is a newer instruct model with optional thinking and tool calling; its two original BF16 safetensors shards total 6,150,235,008 bytes. [SmolLM2-360M-Instruct](https://huggingface.co/HuggingFaceTB/SmolLM2-360M-Instruct/blob/a10cc1512eabd3dde888204e902eca88bddb4951/README.md) primarily supports English; its card explicitly claims function calling for the 1.7B model, not the 360M. Search for SmolLM4 returned no publisher result on 2026-11-04: [search](https://huggingface.co/api/models?author=HuggingFaceTB&search=SmolLM4&limit=100).
- Config dimensions: Qwen3.5 text has 24 layers, 8 query heads, 2 KV heads of 256 dimensions for its six full-attention layers; the other 18 use linear attention, with 16 key/value heads of dimension 128. Native maximum position is 262,144. [Config](https://huggingface.co/Qwen/Qwen3.5-0.8B/blob/2fc06364715b967f1860aea9cf38778875588b17/config.json). Qwen3-0.6B has 28 layers, 16 query heads, 8 KV heads, head dimension 128, config maximum 40,960; its card says 32,768 context, so do not silently treat 40,960 as validated usable context. [Config](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/config.json); [card](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/README.md). SmolLM2-360M has 32 layers, 15 query heads, 5 KV heads, 64 dimensions/head and 8,192 positions. [Config](https://huggingface.co/HuggingFaceTB/SmolLM2-360M-Instruct/blob/a10cc1512eabd3dde888204e902eca88bddb4951/config.json).
- Qwen3, Qwen3.5 and SmolLM2 original cards specify Apache-2.0; Meta's Llama 3.2 uses its own community license and use policy, not Apache. The original Meta model is manually gated; the examined Bartowski conversion's metadata says not gated. The license requires, among other things, providing the agreement and displaying “Built with Llama” on redistribution. [Qwen3.5 card](https://huggingface.co/Qwen/Qwen3.5-0.8B/blob/2fc06364715b967f1860aea9cf38778875588b17/README.md); [SmolLM2 card](https://huggingface.co/HuggingFaceTB/SmolLM2-360M-Instruct/blob/a10cc1512eabd3dde888204e902eca88bddb4951/README.md); [Meta metadata](https://huggingface.co/api/models/meta-llama/Llama-3.2-1B-Instruct); [conversion license](https://huggingface.co/bartowski/Llama-3.2-1B-Instruct-GGUF/blob/067b946cf014b7c697f3654f621d577a3e3afd1c/README.md).

### Inferences

- For this diagram task, start with Qwen3.5-0.8B non-thinking, compare Qwen3-0.6B non-thinking, and use SmolLM2-360M as a small English-oriented baseline. These are hypotheses, not a ranking established by this research.
- Configured maximum context is not a practical browser-memory promise. Test the actual context window, prefill and KV/state memory on target devices.

### Gaps

- No search can establish that there is no other small artifact, or that newer families have no unlisted releases. No reliability, latency, device-memory or diagram-specific evaluation was run.

## Which complete model-file bundles fit below 800,000,000 bytes?

### Takeaway

Several concrete Q4/Q8 GGUF and ONNX files and three WebLLM weight bundles fit, including a 1B Q4 and highly compressed 1.7B choices. Treat the exact-file inventory as a conservative proposed bundle until actual runtime loading confirms dependencies; model files are not total application download size.

### Cited Findings

- The companion [artifact inventory](qwen-smol-artifacts.json) is the authoritative per-file list: each entry has exact filename, bytes, immutable resolve URL, revision, revision commit UTC date, pinned metadata URL, metadata access status, sum, decimal MB and MiB. All 16 pinned model-info endpoints returned HTTP 200; every selected commit is on or before 2026-11-04. Each repository is marked public/non-gated in the metadata. We did not fetch weights or compute their hashes. `HEAD` of six representative large files returned HTTP 302 with matching `x-linked-size`; this establishes an initial public redirect, not final CDN accessibility or a completed download. ### Inferences

- A 1B Q4 or 1.7B Q2/Q3 is a legitimate size candidate, not an automatic exclusion; its proximity to the threshold leaves little space if the product limit also includes runtime assets. Low-bit files should be compared on actual task errors before selection.
- The inventory includes conventional config, tokenizer and generation/template files even when some may not be fetched, but excludes runtime libraries, caches, browser storage overhead and KV/state memory. Smaller model-file size does not mean a smaller total application or peak RAM.

### Gaps

- ONNX graphs were not downloaded or parsed; external-data filenames are taken from the same-variant HF listing, not binary dependency inspection. Additional graph dependencies or runtime-specific tokenization requirements remain a loading gate. Final redirected model/CDN access and checksum were not verified. The separate Llama Q4F16 ONNX total is **1,101,390,838** bytes and is excluded; see [metadata](https://huggingface.co/api/models/onnx-community/Llama-3.2-1B-Instruct-ONNX/revision/82ac69368916173bad498ad390290faab92d4fb0?blobs=true).

## What is documented for browser execution and structured output?

### Takeaway

Native llama.cpp, browser CPU via wllama, WebGPU via WebLLM, and Transformers.js are different compatibility claims. A listed model or valid JSON is not evidence that the browser can load it, or that a generated diagram operation is semantically correct.

### Cited Findings

- [llama.cpp's pinned README](https://github.com/ggml-org/llama.cpp/blob/bbb02c93e9b83255b70ac1a755bb02b0a251f9a7/README.md) explicitly shows native Qwen3.5-0.8B GGUF. [wllama's pinned README](https://github.com/ngxson/wllama/blob/3bb2a46f0dab0b924e8cd992b85e8881c3d3a859/README.md) describes a llama.cpp WebAssembly binding capable of browser CPU inference and also describes WebGPU. This does not establish that its distributed binary includes the exact Qwen3.5 architecture or low-bit kernels; check the exact wllama release and run it.
- [WebLLM's pinned model list](https://github.com/mlc-ai/web-llm/blob/d0a8ade825657484465d1b5518df54c79a73499a/src/config.ts) names Qwen3.5-0.8B Q4F16_1, Qwen3-0.6B Q4F16_1 and SmolLM2-360M Q4F16_1 with WebGPU WASM model libraries. This is documented WebGPU availability, not browser-CPU inference and not a test of these pinned files. Its Qwen3.5 [MLC chat config](https://huggingface.co/mlc-ai/Qwen3.5-0.8B-q4f16_1-MLC/blob/0ec138972555613c1d7812a821778ad0398c8790/mlc-chat-config.json) has `qwen2` conversation formatting and stop IDs 151643/151645, whereas the original [Qwen3.5 text config](https://huggingface.co/Qwen/Qwen3.5-0.8B/blob/2fc06364715b967f1860aea9cf38778875588b17/config.json) uses EOS 248044. This mismatch is an unresolved compatibility risk, not proof of a bug: validate prompt, tokenization and stopping before using it.
- The [Qwen3 ONNX conversion card](https://huggingface.co/onnx-community/Qwen3-0.6B-ONNX/blob/58ca03a5e7b354b480b1a82b34bde8dc7b854cc0/README.md) demonstrates Transformers.js using `device: "webgpu"`, `dtype: "q4f16"`. A CPU-oriented INT8 artifact also exists, but its existence alone does not document that this exact graph runs in browser WASM. Qwen3.5 text ONNX has `qwen3_5_text` configuration and external shards; compatibility with a particular Transformers.js/browser runtime remains untested. [Config](https://huggingface.co/onnx-community/Qwen3.5-0.8B-Text-ONNX/blob/25cdf33f386b487a25f3d743e86442517bdb77ff/config.json).
- The Qwen cards describe tool use with supporting templates and parsers, rather than an error-free guarantee; SmolLM2 explicitly limits its function-calling claim to 1.7B. [Qwen3.5](https://huggingface.co/Qwen/Qwen3.5-0.8B/blob/2fc06364715b967f1860aea9cf38778875588b17/README.md); [Qwen3](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/README.md); [SmolLM2](https://huggingface.co/HuggingFaceTB/SmolLM2-360M-Instruct/blob/a10cc1512eabd3dde888204e902eca88bddb4951/README.md).

### Inferences

- First experiment: Qwen3.5 GGUF Q4_0 in a confirmed compatible wllama CPU build, non-thinking; compare Qwen3 Q8 and Smol Q8 on the same English diagram requests. If CPU compatibility fails, test the documented WebGPU WebLLM route separately, after resolving the Qwen3.5 chat-config mismatch. Check actual downloaded files, browser startup, context, throughput, memory and the schema parser.
- Parse and validate JSON/schema and separately compare intended versus generated operations, including wrong and extra actions and abstentions. Syntactically valid JSON, successful tool invocation and the model's own confidence do not establish semantic correctness or calibrated confidence.

### Gaps

- No runtime, browser, device, model inference, tool-calling or performance test ran here. No measured accuracy or calibrated confidence claim is available. Wasm, model library and application assets are outside these model-file totals.
