# Browser runtimes, payloads, and safe diagram extraction

Cutoff: **2026-11-04**. Public docs/source/metadata only. **No model downloads, conversion, inference or runtime observations.** Documentation is not execution. Asset metadata: `runtimes-assets.json`.

## 1. Which browser paths are documented?

### Takeaway

First CPU-browser candidate: **pin wllama 3.8.1, explicitly set `n_gpu_layers: 0`, initially `n_threads: 1`, self-host matching modern/compat assets, and start with a small dense GGUF instruction model**. Keep existing encoders on their current Transformers.js/WASM path; test upgrades separately. This is a recommendation for future verification, not a successful new-model execution claim.

**Precision is a graph/kernel question, not a filename guarantee**

- Transformers.js 3.8.1 defaults unspecified WASM dtype to **q8**, other devices to **fp32**. Suffixes: q8→`_quantized.onnx`, int8→`_int8.onnx`, q4→`_q4.onnx`, q4f16→`_q4f16.onnx`. This selects an exported graph, **not runtime conversion or guaranteed integer arithmetic**. Explicit dtype prevents accidental larger downloads on device changes. FP16 WebGPU checks optional `shader-f16`. [dtype source](https://github.com/huggingface/transformers.js/blob/2ec882e739e4cb461f8d440d4d7394cbf5372429/src/utils/dtypes.js), [graph dispatch](https://github.com/huggingface/transformers.js/blob/2ec882e739e4cb461f8d440d4d7394cbf5372429/src/models.js#L191-L247)
- ORT says WASM supports ONNX operators while GPU EPs support subsets: not a guarantee of every contrib op/opset/dtype/fusion. Production ORT commit **89f8206ba4** lists WebGPU **MatMulNBits/DequantizeLinear**, but not **DynamicQuantizeLinear/MatMulInteger**. CPU dynamic-int8 encoder success therefore does not establish a GPU path. [Overview](https://onnxruntime.ai/docs/tutorials/web/), [pinned GPU list](https://github.com/microsoft/onnxruntime/blob/89f8206ba4/js/web/docs/webgpu-operators.md)
- At that revision CPU **MatMulNBits** accepts 4-bit weights; optimized execution requires MLAS QNBit dispatch, installed for native x86/ARM rather than WASM in `platform.cpp`. Absent dispatch it **dequantizes N×K weights into a temporary FP32 matrix and uses float GEMM**. This is a source-derived expectation for the old production build, not a new-model profile or every 2026 ORT release. Distinguish (1) packed q4 kernels, (2) dynamic-int8 activation/weight arithmetic, (3) weight-only dequantization→FP32 MatMul. Download bits do not determine compute precision or peak RAM. [fallback](https://github.com/microsoft/onnxruntime/blob/89f8206ba4/onnxruntime/contrib_ops/cpu/quantization/matmul_nbits.cc#L432-L535), [availability](https://github.com/microsoft/onnxruntime/blob/89f8206ba4/onnxruntime/core/mlas/lib/qnbitgemm.cpp#L69-L99), [platform](https://github.com/microsoft/onnxruntime/blob/89f8206ba4/onnxruntime/core/mlas/lib/platform.cpp)
- ORT Web needs **`externalData: [{path, data}]`**: path must match the graph's stored location. Transformers.js 3.8.1 `use_external_data_format` accepts boolean/count/per-file mapping and constructs `<graph>.onnx_data`, `_data_1`, etc. Arbitrary adjacent sidecar filenames are insufficient. Its nested async Promise executor lacks proper outer rejection; 4.3.2 notes the hang fix. [ORT docs](https://onnxruntime.ai/docs/tutorials/web/large-models.html#external-data), [3.8.1 loader](https://github.com/huggingface/transformers.js/blob/2ec882e739e4cb461f8d440d4d7394cbf5372429/src/models.js#L269-L318), [fix release](https://github.com/huggingface/transformers.js/releases/tag/4.3.2)

### Inferences

- Dense wllama CPU reduces initial integration assumptions, not necessarily diagram errors. Keep encoder heads/tokenizer/decoder on ORT WASM unless separately verified. Upgrades require new pins/operator audits, not extrapolation from old kernels.

### Gaps

- Exact new-model browser paths remain **unverified**: modern/compat, single/multithread, GPU and alternative conversions are separate acceptance cases.

**Deployment restrictions**

- Modern wllama requires **JSPI/MEMORY64**; compat uses **Asyncify/no MEMORY64**. Maintainer docs describe Safari/older-browser fallback and lower compat performance. Default handling exempts Firefox; without JSPI Firefox can disable WebGPU, or force compat with a performance warning. These are support statements, not measurements here. Self-host version-matched fallback assets, avoiding implicit CDN dependencies. [Compat docs](https://github.com/ngxson/wllama/blob/b68fd6427063266176bb0054befe9ff70b3258f1/compat/README.md)
- README warns about **2GB per-file/ArrayBuffer** and recommends **≤512MB GGUF chunks**. Build still caps WASM memory at **4096MB despite MEMORY64**. Shared-memory setup starts at 128MiB, tries maximums downward from 4096MiB for mobile allocation failures. Splitting does not reduce total model/context/scratch memory. ORT distinguishes ~2GB ArrayBuffer/protobuf and WASM32 4GB limits. [README](https://github.com/ngxson/wllama/blob/b68fd6427063266176bb0054befe9ff70b3258f1/README.md), [flags](https://github.com/ngxson/wllama/blob/b68fd6427063266176bb0054befe9ff70b3258f1/CMakeLists.txt), [allocation](https://github.com/ngxson/wllama/blob/b68fd6427063266176bb0054befe9ff70b3258f1/src/workers-code/llama-cpp.js#L116-L138), [ORT limits](https://onnxruntime.ai/docs/tutorials/web/large-models.html)
- WASM multithreading needs SharedArrayBuffer/atomics and isolation, normally **COOP `same-origin` + appropriate COEP**. wllama falls back to single-thread; `n_threads: 1` forces it. ORT `env.wasm.numThreads = 1` disables threads. Do not assume normal GitHub Pages can set custom headers: a **same-origin COI service worker** is a third-party documented workaround, with first-load reload, HTTPS/localhost requirement and no CDN worker. Such a hosting change needs separate approval/testing. [wllama threading](https://github.com/ngxson/wllama/blob/b68fd6427063266176bb0054befe9ff70b3258f1/README-dev.md#L42-L52), [ORT flags](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html), [GH Pages workaround](https://github.com/gzuidhof/coi-serviceworker)
- COEP requires auditing cross-origin assets/redirects for CORS/CORP. Restrictive CSP must allow intended fetch origins, generated worker blobs where used, and WASM via **`'wasm-unsafe-eval'`**, not arbitrary model-generated code. ORT's blob proxy worker cannot handle WebGPU EP. [COEP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cross-Origin-Embedder-Policy), [CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src#unsafe_webassembly_execution), [ORT proxy](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html#envwasmproxy)
- `navigator.gpu` is insufficient: adapter, features, requested limits, driver/memory matter. Baseline **maxStorageBufferBindingSize = 134,217,728 B (128MiB)**; **maxBufferSize = 268,435,456 B (256MiB)**, not total VRAM. Larger supported limits can be requested; FP16 needs optional **shader-f16**. q4f32 remains a GPU path. WebLLM checks required features and warns below a 1GiB storage-binding limit. Desktop availability does not establish mobile/iOS usability or memory. [Limits](https://developer.mozilla.org/en-US/docs/Web/API/GPUSupportedLimits), [features](https://developer.mozilla.org/en-US/docs/Web/API/GPUAdapter/features), [WebLLM checks](https://github.com/mlc-ai/web-llm/blob/6897fadc2bed9a5a7940265dd80220f83ca184e7/src/engine.ts)
- wllama defaults to **OPFS** via a pluggable backend, with size/metadata checks for interrupted downloads and deletion API. Production Transformers uses **CacheStorage** with versioned keys. Origin-scoped storage can be quota-limited/evicted, cleared or lost in private mode; disk cache is not active model RAM or guaranteed offline readiness. Plan download/retry/clear controls and storage-estimate/persistence policy. [wllama cache](https://github.com/ngxson/wllama/blob/b68fd6427063266176bb0054befe9ff70b3258f1/src/cache-manager.ts), [local keys](../../../docs/js/neural.js#L620-L660), [storage lifecycle](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

### Inferences

**Memory worksheet — calculated/planning values, not measured peaks**

- Budget separately: disk quantized weights; downloaded/copied bytes; tokenizer/config/JS; CPU packed weights and dequantization buffers; activations/scratch; context/KV; logits/output; GPU weights/staging/cache; other resident readers. Do not assert three full copies always exist: wllama JSPI/Asyncify can read **Blob.slice** without full input allocation, while fallback HeapFS holds the full file in RAM even with GPU offload. [File-access design](https://github.com/ngxson/wllama/blob/b68fd6427063266176bb0054befe9ff70b3258f1/README-dev.md#L64-L99)
- Full-attention decoder KV approximation, one sequence: **`2 × layers × KV_heads × head_dim × cached_tokens × element_bytes`**, before padding/metadata. Cache precision is not weight precision; generated tokens also consume cache. **Qwen3-0.6B actual config:** 28 layers, 8 KV heads, head_dim128, no sliding: FP16 KV **112KiB/token, 224MiB at 2048, 448MiB at4096**; FP32 doubles. [Pinned config](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/config.json)
- **Hybrids need actual configs.** LFM2.5-350M: six attention + ten conv layers, 8 KV heads, hidden1024/16 attention heads, conv_L_cache3. Attention-only FP16 term **12KiB/token, 48MiB/4096**, plus conv state/scratch. Qwen3.5-0.8B: six full-attention + eighteen linear-attention layers, full head_dim256, 2 KV heads: also **12KiB/token**, plus recurrent/conv state; config requests FP32 SSM state. These are conditional attention-cache calculations, not total RAM. Sliding-window models likewise require actual layer schedule/window and runtime allocation, not blanket substitution of advertised window length. [LFM config](https://huggingface.co/LiquidAI/LFM2.5-350M/blob/9921cd4d82c0e3986887aa4b376f9446729ef8a3/config.json), [Qwen3.5 config](https://huggingface.co/Qwen/Qwen3.5-0.8B/blob/2fc06364715b967f1860aea9cf38778875588b17/config.json)
- Logits: **batch × logit_positions × vocabulary × output_element_bytes**. Qwen3 vocab151936 means ~**0.58MiB** per FP32 position, but ~**1.16GiB** for2048 positions if materialized. Inspect whether an export emits last-token logits only. Encoders lack autoregressive KV but need sequence-dependent activations/head outputs; unfused attention scores can be quadratic. [Vocabulary](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/config.json)
- Planning envelope: 800MB weights + one 800MB copy = **1.6GB decimal before context/activations**; add Qwen3-like FP16 KV4096 → **~2.07GB before scratch**. A copy can matter more than 9MB runtime. Lazy-load the LLM, measure alone then with the five readers, explicitly unload sessions/workers; deleting disk cache does not free a live model. [wllama unload](https://github.com/ngxson/wllama/blob/b68fd6427063266176bb0054befe9ff70b3258f1/src/wllama.ts#L913-L917)
- Bandwidth lower-bound arithmetic only: **800,000,000B ×8 /20Mbit/s =320s; at100Mbit/s=64s**, excluding overhead/stalls/runtime/compile/load. 400MB halves these. Cache-warm startup is separate, not assumed instantaneous.

### Gaps

- No deployed-header/browser/quota/COI or RAM tests. Usable mobile memory cannot be inferred from API maxima. Full Transformers4.3.2/WebLLM fetch inventories remain unverified; hashes are metadata, not independently downloaded/hash-checked.

## 3. Constrained output, confidence, and fair testing

### Takeaway

Use **bounded action proposals → schema/legend validation → confidence gate → existing drawing engine**, never generated JS. Grammar proves syntax, not correct targets/values, complete multi-command extraction or calibrated confidence.

### Cited Findings

- wllama3.8.1 exposes per-request **`grammar?: string`**, and chat **`response_format: {type:'json_schema', json_schema:{name,schema,strict?}}`** (also json_object/text). Types expose logprobs/top_logprobs, return_tokens, max_tokens, template kwargs, streaming. Old v2 samplingInit examples are obsolete. [Sampling types](https://github.com/ngxson/wllama/blob/b68fd6427063266176bb0054befe9ff70b3258f1/src/types/types.ts), [chat types](https://github.com/ngxson/wllama/blob/b68fd6427063266176bb0054befe9ff70b3258f1/src/types/oai-compat.ts)
- Pinned llama.cpp schema→GBNF supports a **subset**: unsupported constructs can be silently skipped; docs list broken prefixItems/nested refs, no remote refs in C++, integer-only numeric bounds, anchored patterns, missing uri/email formats, no patternProperties/uniqueItems/contains/not/conditionals/dependentSchemas; mixing properties with anyOf/oneOf is problematic. additionalProperties defaults false. **Schema is not injected into the prompt** except tool calling: explain format/legend too, and independently validate JSON. [Pinned grammar guide](https://github.com/ggml-org/llama.cpp/blob/46ca246de9bb1c35269722a6240d37d9dfd79cad/grammars/README.md#json-schemas--gbnf)
- WebLLM API differs: **`response_format:{type:'json_object',schema:JSON.stringify(schema)}`**, or `{type:'grammar',grammar:ebnf}`, or structural_tag. Its public union does not use wllama's top-level json_schema. It offers logprobs/top_logprobs and warns about whitespace loops/truncated JSON at finish_reason length. ### Inferences

**Proposed contract — not implemented/evaluated**

- Use `{status,actions:[...],unresolved:[...]}` with bounded arrays, legend enums, typed arguments, literal names/references/spans. Preserve whole10–20-sentence requests. Pre-register limits; **abstain visibly on overflow**, never truncate silently for speed.
- Define offset units (e.g. JS UTF-16), check spans against immutable input. Grammar cannot prove a span/target exists or a request was omitted. Preserve pronouns/“the new one” for existing context reasoning; do not invent targets. Validate every action/role/value/reference before engine execution.
- Distinguish uncertain/unsupported/invalid/truncated/runtime-failure statuses. Never execute partial streamed JSON; preferably validate the **full request** because later text can correct earlier commands. Incremental execution needs explicit correction/rollback policy before timing “first command”.
- Model-written “confidence0.99” and grammar-renormalized probabilities are not calibration. If pre-grammar scores are available, preregister action-level aggregates excluding punctuation/forced keys, calibrate executed-action correctness out of fold. If unavailable, hold execution and report the blocker; a new confidence classifier is not implicitly authorized.
- Report `(wrong+extra)/(correct+wrong+extra)` confidently-wrong rate, requests done right/asked/wrong, extras, risk–coverage, AUROC where defined, seen/unseen triggers, and cost10 `100×(correct−10×(wrong+extra))/requested`. Pick threshold once by registered calibration protocol; missing confidence means abstain. Separate syntax/semantics/cuts/omissions/unresolved references in root-cause analysis.
