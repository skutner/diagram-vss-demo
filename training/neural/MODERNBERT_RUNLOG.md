### A converter fix for roles the layout cannot hold, and M3 on it: declared before any of it runs (22:08)

- **What the code does today** (read, not run): `make_roles.py` encodes any role holding a `mention(...)` as `fill=description` and keeps only its first mention (`filler_kind`; the desc heads take the first mention per role). A second mention, or a name or `$new` beside it, is dropped silently. `neural.js` reads a `fill=context` role as the shared context reference (the last shape created or named), and the confidence counts context fills (`ctx_fill`). No switch today encodes a role the layout cannot hold as anything other than one description.
- **Fix:** `ROLE_TOO_RICH=context` in `make_roles.py`, with the same switch in the round trip and the builder. A role whose value holds several mentions, or a name or `$new` beside a mention, is encoded as `fill=context`: no description heads and no tags from it. The reader then learns to leave such a role to the context, where the confidence can hold it, instead of learning part of it as all of it. This is a converter fix using a class the reader already has. The labels (wires) are not changed. The rule is the same for every role key and every folder.
- **It holds when:**
  - every trained folder passes the round-trip gate (>= 95% right, reference only or asked; <= 1% silent);
  - a build without the switch is byte-identical to today's;
  - the rows it changes in the older folders are counted and listed before training.
- **M3 then = M2n's list + `nl_p1` (adjudicated) + `ROLE_TOO_RICH=context`, seed 0, compared with M2n.** The fix changes about 50 rows of the older folders (round-trip counts), so it is not run as an arm of its own tonight: its effect cannot be separated from `nl_p1`'s, and the report says so. M3's threshold is the plan's: on `nl_a` development, the cost score rises by >= 2 points with its 95% interval above 0; the unseen-trigger and paraphrase numbers do not fall; no loss shown on fresh2, short3, `scenes_test`.
