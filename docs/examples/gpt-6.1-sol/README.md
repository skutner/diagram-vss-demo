## Executable format and playback

Each wire is one line of the application's executable dialect, for example:

```sop
@a command action=create shape=circle name=Hub color=blue
@q question ask=count
```

This is the dialect of `docs/js/logic.js`, not the multiline VSS reader/writer representation. A `# turn-N` header selects a turn; selected executable lines are joined with `\n`, without a final newline, for the program hash. Blank and comment lines are excluded. Empty sections state their no-op or unsupported reason explicitly.

The tab owns its world, engine, results and undo/redo stacks. It starts from the common opening SOP by executing it itself. A fixed example carries stable occurrence/run identity; its original text remains inspectable beside effective playback text. The binder changes parsed name arguments and declarations, preserving quoted labels, unrelated identifiers and wire references. A single reserved namespace supports repeated runs and shape/group collisions.

Scenarios start in a new drawing area, following the existing player. Scene clear commands execute an idempotent, undoable `action=clear` through the engine and remove shapes, connections and groups from the whole drawing. Clear preserves defaults, name counters and drawing frames. Global selectors, rules and questions retain engine semantics, so earlier areas can affect results. Shape queries follow the legend's distinction between ordinary items and background/zone panels.

`initialContext` describes the canonical validation fixture: opening drawing for each quick entry, empty world for scenarios/scenes. Live quick examples use the current world: for example, “the green circle” remains a dynamic mention. A missing or ambiguous prerequisite is rejected before mutation. Questions are executed against the actual current state; the UI never displays a fabricated saved answer.

Playback validates source identity, exact input and hashes, program sections, sequence and the actual state/history/context since its previous turn. Missing, stale, edited, unrecognized or interrupted input produces an explicit unavailable result, without fallback to another reader. Typed direct SOP retains direct engine behavior and is not attributed as a generated translation. An intentional no-op creates no history entry.
